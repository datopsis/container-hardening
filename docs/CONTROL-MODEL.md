# Control model

How a Datopsis image states what it contributes to each NIST SP 800-53 Rev 5
control, and what it hands to someone else, so that every image states it the
same way.

Where it lives, and why, is [ADR-0004](adr/0004-derive-the-control-baseline-here-validate-components-there.md).

## What each image produces

Each image repository keeps an **OSCAL component definition** describing what
that image contributes to each control. It is not a System Security Plan and
cannot become one: an SSP depends on the deployed boundary, the organization's
parameters, and an assessor's judgement.

The reader is an external assessor who will import it into their own package.
That reader decides what the component definition must make unambiguous.

This repository keeps the **[control baseline](controls/README.md)**: the
origination every image starts from, for every control in the High baseline and
every further control the standard reaches. An image's component definition is
checked against it by [`scripts/check-component.py`](../scripts/check-component.py).

## Origination is mandatory

A control without a machine-readable origination can be read as a claim that
something is satisfied, so every control carries one, and a responsible role
that matches it.

| Origination | Meaning | Responsible role |
| --- | --- | --- |
| `image-owned` | The image implements this, and its repository can evidence it | `image-project` |
| `deployment-configured` | Satisfied only if the deployment configures it correctly; the image makes it possible | `deployment-profile` |
| `host-inherited` | The host or orchestrator satisfies this; the image relies on it | `host-orchestrator` |
| `organization-inherited` | The organization satisfies this outside any technology | `organization` |
| `not-applicable` | The control does not apply to a component of this kind, with a reason | none |
| `research-required` | Not yet determined; not a claim in either direction | `image-project` |

**`image-owned` is the only value that asserts the image satisfies anything.**
Every other value is a handoff, and names who has to act.

## The verification pointer

**A control may not be `image-owned` without a verification pointer.** It
carries two:

- a `criterion`: the [image criteria](standard/criteria.md) the claim rests on,
  every one of which is *required*, never a target
- a `requirement`: at least one requirement identifier that the image's own
  repository states, whose evidence that repository resolves

The criterion says what property the standard expects. The requirement says
that this image has committed to it, in its own words, with its own test. The
second is the part that matters most: it stops a control asserting an
obligation the image never stated. A component definition that cites a
criterion but no requirement of its own is claiming the standard's work as the
image's.

## How the baseline is derived

The baseline is generated by
[`scripts/build-control-baseline.py`](../scripts/build-control-baseline.py), and
for most controls nobody chooses the answer:

1. A control that a **required image criterion** reaches is `image-owned`.
   "Reaches" means through the criterion's anchors: the criterion cites an SRG
   rule, and the [crosswalk](crosswalk/README.md) says that rule reaches the
   control.
2. Otherwise, a control that only **platform or host expectations** reach takes
   their origination, which each expectation states.
3. Otherwise, a **family default** applies, for families no image can meet:
   personnel, physical, training, planning.
4. Otherwise the control is `research-required`.

Where that derivation gives the wrong answer, a **determination** in
[`artifacts/control-determinations.json`](../artifacts/control-determinations.json)
overrides it, with its reason. The generator refuses:

- a determination that repeats what derivation already gives, so the file holds
  only decisions
- a control reached by expectations that disagree about origination, until a
  determination settles it
- an `image-owned` control resting on a target criterion, or on none
- a handoff that names no expectation

`research-required` in the baseline is not a gap. It marks the controls whose
answer depends on what the image does: a database authenticates users and a
static file server does not. Those are the ones each image decides.

## What an image's component definition must do

One entry per control, carrying properties in the namespace
`https://datopsis.example/ns/oscal`. The namespace is an identifier, not a URL
to resolve, and it is fixed: changing it would orphan every property written
against it.

```json
{
  "control-id": "cm-7",
  "props": [
    {"name": "origination", "ns": "https://datopsis.example/ns/oscal", "value": "image-owned"},
    {"name": "criterion", "ns": "https://datopsis.example/ns/oscal", "value": "IMG-06"},
    {"name": "criterion", "ns": "https://datopsis.example/ns/oscal", "value": "IMG-07"},
    {"name": "requirement", "ns": "https://datopsis.example/ns/oscal", "value": "L1-IMG-002"},
    {"name": "assessment-method", "ns": "https://datopsis.example/ns/oscal", "value": "test"},
    {"name": "cross-reference", "ns": "https://datopsis.example/ns/oscal",
     "value": "disa-gpos-srg:V-203637", "class": "disa-gpos-srg"}
  ],
  "responsible-roles": [{"role-id": "image-project"}],
  "description": "What the image does, in terms an assessor can check.",
  "remarks": "Limitations, and what the image cannot do."
}
```

`check-component.py` holds these rules:

| Rule | Why |
| --- | --- |
| Exactly one `origination`, from the table above | An entry with none, or two, is ambiguous to an assessor |
| A `responsible-roles` entry matching the origination | A handoff that names nobody hands off to nobody |
| `image-owned` carries a required `criterion` and a stated `requirement` | The verification pointer |
| `image-owned` cites every criterion the baseline gives for that control | The claim rests on all of them, not the convenient one |
| Only `image-owned` carries an `assessment-method` | An assessment of something the image does not do is one the image cannot perform |
| The origination matches the baseline, unless the baseline says `research-required` | One image may not quietly take a different position from the standard |
| Every baseline control is present | An absent control reads as an unconsidered one |
| `cross-reference` is `<source-id>:<reference>` | A mapping names the pinned revision it was made against |

An `image-owned` control with no `remarks` draws a warning. One with no
limitations is usually one nobody has thought about.

A position that differs from the baseline is a **deviation**, recorded in the
image's [hardening profile](TAILORING.md#deviations) with a reason and an
expiry. Run with `--profile`, the checker honours active deviations; without
one, or once it expires, the difference is a violation.

## Running it

From an image repository, against a pinned revision of this one:

```sh
python ../container-hardening/scripts/check-component.py \
    artifacts/oscal/component-definition.json \
    --requirements docs/L1-REQ.md docs/L2-REQ.md docs/L3-REQ.md \
    --profile artifacts/hardening-profile.json
```

`--requirement-pattern` sets the regular expression that finds requirement
identifiers; the default matches requirement headings of the form
`### L1-IMG-001`.
`--allow-incomplete` reports absent controls as warnings while a component
definition is being written. It exits non-zero on any violation.

## Enforcement

In this repository, `tests/test_controls.py` re-derives the committed baseline
from the committed standard, crosswalk, and determinations, without the source
packages. It fails if the standard changed and the baseline was not regenerated.
It also runs the checker against constructed component definitions, one per
rule, to prove each rule fails when it should. The weekly source verification
regenerates the baseline from the pinned NIST catalogue.

In each image repository, enforcement is that repository running
`check-component.py` in CI. Until it does, this model is a convention for that
image, and conventions are what get dropped under deadline.
