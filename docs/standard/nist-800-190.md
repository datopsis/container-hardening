# NIST SP 800-190

**NIST Special Publication 800-190, *Application Container Security Guide***
(Souppaya, Morello, and Scarfone, September 2017) is the one NIST publication
written specifically about container security. It is pinned in
[`artifacts/sources.json`](../../artifacts/sources.json) as `nist-sp800-190`,
and it is current: NIST has published no revision or draft since.

This standard follows it. Where the two differ, this page says so. The DISA
[Container Hardening Process Guide](process-guide.md) requires images to be
"consistent with NIST SP 800-190" (Appendix B), so following 800-190 is also
how this standard meets that part of the DISA guide.

## How it is organised, and how this page follows it

SP 800-190 divides a container deployment into five tiers: **image, registry,
orchestrator, container, and host OS**. Section 3 names the major risks to
each, and Section 4 gives a countermeasure for each risk, plus hardware
countermeasures in §4.6. That is 24 countermeasures.

This standard divides the same ground into three layers: image, platform, and
host. The registry, orchestrator, and container tiers are all the platform
here, because one party runs them. Each countermeasure below is assigned to the
layer that has to act on it, and to the criteria or expectations that
implement it. **Every countermeasure is listed.** `tests/test_standard.py`
fails if one is missing or if an identifier here does not exist.

Many of SP 800-190's countermeasures are addressed to "organizations" and
describe tooling the platform operator runs: vulnerability management
dashboards, runtime anomaly detection, network filtering. An image cannot run
those tools. Its part is to be the kind of image they work well on: small,
declared, signed, and predictable. Where a countermeasure is the platform's,
the image's contribution is named alongside it.

## Where this standard differs from SP 800-190

**Signatures are not claimed to be from a validated module.** SP 800-190
§4.1.5 asks for images to be identified by signature "using a NIST-validated
implementation". Datopsis images are signed with cosign, and the standard
[does not claim FIPS validation](README.md#what-this-standard-refuses) for
anything. The signature establishes identity and integrity; it is not
presented as a validated cryptographic operation.

**Minimal bases are UBI, not Alpine.** §4.1.2 gives Alpine Linux and Windows
Nano Server as examples of minimal bases. Datopsis images use Red Hat UBI 9
Micro and Minimal, which are minimal in the same sense and are what the DoD and
DISA guidance assumes.

**Configuration compliance scanning is a target.** §4.1.2 asks for validation of
image configuration settings with centralized reporting. The standard meets the
settings SP 800-190 names, non-root users above all, as required criteria, but
an OpenSCAP scan against an agreed rule selection remains
[target IMG-T3](criteria.md#img-t3-compliance-scan) until that selection exists.

**The image declares its behaviour; it does not rely on it being learned.**
§4.4.4 describes runtime tools that profile applications "using behavioral
learning". The standard goes further for its own images: each declares its
expected behaviour ([IMG-30](criteria.md#img-30-expected-behaviour-is-declared)),
so the profile is known before the first run instead of learned from it.

## What SP 800-190 says beyond Section 4

**Section 6, life cycle.** Planning, forensics, incident response, and
disposition are organizational activities. The image supports them by being
immutable and declared: a process that is not in the image's declaration is
evidence in itself, which §6.2 observes.

**Appendix B, 800-53 controls.** SP 800-190 lists the 800-53 controls most
relevant to containers. It lists them against **Revision 4**, not Revision 5,
so this repository cites that table but does not join it to the
[crosswalk](../crosswalk/README.md), whose spine is Revision 5. Its Table 3
notes that containers can partly meet SI-14 (non-persistence) and SC-39
(process isolation) by construction; those are recorded when controls are
determined.
